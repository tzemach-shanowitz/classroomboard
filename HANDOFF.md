# ClassroomBoard handoff

ClassroomBoard is a Classroomscreen-style classroom board for a SMART Board, computer or phone. No framework: plain JavaScript files loaded by `app/index.html`, plus one esbuild bundle (`cloud.js`) for Firebase. It works with no account (data in the browser's localStorage). Signing in saves and syncs it.

Live: https://classroomboard.web.app (landing at `/`, app at `/app/`). Old domain: https://my-smart-classroom-fe1ad.web.app.

## Not in this repo (on purpose)
No credentials, tokens, real student names or personal Drive folder IDs. Three source edits were made for this export, compared with the deployed build:
1. Firebase web config, the Drive API key and shared folder IDs moved to `config.local.json` (git-ignored; see `config.example.json`).
2. The owner's three personal Google Drive folder IDs became `window.__PERSONAL.{libFolder,presFolder,sharedFolder}` (default `root`). Set them to restore the original behavior for that one account.
3. A personal teacher name in the legacy-only default schedule was replaced with a generic label.
`app/cloud.js` is generated and git-ignored. Rebuild it (below).

## Requirements
- Node 22 (developed on v22.23.5), npm.
- Dev: `npm install`, then serve `app/` as static files, e.g. `python3 -m http.server 8099 -d app`. Add `?demo=home` (or another tool name) for isolated fictional data.
- Build the Firebase bundle: `npx esbuild cloud-src.js --bundle --minify --format=iife --outfile=app/cloud.js` (put `config.local.json` next to `cloud-src.js` first).
- Deploy layout: Firebase Hosting serves `dist/`: landing page at `dist/index.html` (from `landing/`, with `landing/img`), the app copied to `dist/app/`. `/review/` is generated by `tools/` (puppeteer against the live site). Deploy: `npx firebase-tools deploy --only hosting,firestore:rules` (needs `firebase login` or a CI token, which you provide yourself).
- Service worker: `app/sw.js` has a cache name (`classroom-vNN`) and a FILES list. Bump the name on every deploy. Add every new JS file to FILES. Users must fully close and reopen the app once to get a new version.

## Libraries
firebase (Auth + Firestore, bundled), pdfjs-dist 3.11 (PDF viewer, in `app/vendor/`), esbuild (build only). Dev/testing: puppeteer-core (not in package.json).

## Firebase
Project ID `my-smart-classroom-fe1ad`. Hosting sites: `classroomboard` (main) and `my-smart-classroom-fe1ad` (old). Services: Authentication (Google and email/password), Firestore, Hosting. Firestore data is `users/{uid}/...`, each document a user-data key stored as a string. Rules (`firestore.rules`): only the signed-in user may read or write `users/{uid}/**`. Guests never touch Firestore.

## External hostnames called
- `www.googleapis.com` (Drive v3, Google Identity / Firebase Auth)
- `*.firebaseapp.com`, `firestore.googleapis.com`, `identitytoolkit.googleapis.com`, `securetoken.googleapis.com` (Firebase)
- `accounts.google.com` / `apis.google.com` (Google sign-in popup)
- `drive.google.com`, `docs.google.com` (viewing Drive files and Slides)
- `www.youtube-nocookie.com` (embedded videos)
- Fonts and map or weather calls: none (all vendored). Check `grep -rnE "https?://" app/*.js` to re-verify.

## Config names
`config.local.json`: `firebase.{apiKey,authDomain,projectId,storageBucket,messagingSenderId,appId}`, `driveApiKey`, `sharedFolderIds`. `window.__PERSONAL.{libFolder,presFolder,sharedFolder}` is optional. Deploy token (if CI is used): `FIREBASE_TOKEN`.

## Google Drive OAuth scope
`https://www.googleapis.com/auth/drive.readonly` (read only). The token lasts about an hour and is never stored by the server.

## Data and guests
All settings live in localStorage under the `sc.` prefix (`cfg` holds UI/toolbar/labels, `sched.<date>`, `studentLists`, `libLinks`, `presLinks`, `beh.state`, `anno.*`). Signed-in users sync those keys to Firestore. A guest keeps data only in that browser. New users start blank. The `LEGACY` flag (set by the migration marker `mig.roster1`) preserves the owner's original defaults; do not remove it without migrating his data.
Backup of a user's cloud data: read `users/{uid}` documents (Firestore export, `gcloud firestore export`, or the in-app Settings > Privacy & data > Backup).

## Feature status
Working (tested only in desktop Chrome with demo data): clock and Hebrew date, timer, whiteboard and annotation, schedule editor, name picker and wheel, supplies, behavior and stars, 17+ kit widgets (traffic light, poll, scoreboard, groups, text, stopwatch, dice, calendar, sound level and more), saved links, Drive library and presentations, native Settings (theme, accent, size, interface language en/he/yi, wording presets), landing page and `/review/` page.
Still legacy-looking: Library and Presentations browser popups, parts inside a few widget sheets, first-run welcome modal, PDF viewer. Hebrew and Yiddish text is an unreviewed draft. Large interface size does not scale old modals.

## Known bugs and unverified
- NOT tested on a real SMART Board, real phone or real teachers. Do not claim SMART compatibility until it is.
- No automated test suite in the repo. Tests were ad hoc puppeteer scripts.
- Universal-defaults work (neutral toolbar, onboarding, guest-to-account merge) is planned, not shipped.

## Requirements the owner asked to keep
Free services only. Three traffic-light colors (orange only for behavior marks: green 0, yellow 1, orange 2, red 3). Student-facing text in Yiddish/Hebrew, teacher settings in English. Hebrew date stays the default under the clock for his account. Login stays open to anyone. Never remove features or delete saved data. Only fictional names in public artifacts.

## History
The project was developed outside git. This repo is a single sanitized snapshot of the current build (v99). Earlier checkpoints were not imported because they contain the personal values removed above.

## Developer Hub
`developer-src/gen.py` generates the open read-only hub (static HTML, JSON, Markdown); `developer-site/` is the generated output deployed at `/developer/`. Submissions go through GitHub Issues. Protected write API and MCP are not built (they need hosting beyond the free tier).

## Config
Copy `config.example.json` to `config.local.json` (git-ignored) and fill in your own Firebase web config, optional Drive API key and shared folder IDs before building `cloud-src.js`.
